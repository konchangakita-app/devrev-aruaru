Computerデスクトップアプリが繋がらない時は
wss(443)の通信許可を確認

あるある度 Computer • 2026-09-04
症状

Web版は動くのに、デスクトップアプリだけ繋がらない

社内ネットワークやプロキシ／ファイアウォール配下で Computer デスクトップアプリを使うと、 ログインやエージェントの応答が進まず接続できない。ブラウザの Web 版は問題なく動くのに、 デスクトップ版だけが繋がらない、というパターンで気づくことが多い。

原因

WebSocket(wss) / 443 がブロックされている

デスクトップアプリは認証とエージェント呼び出しにインターネット接続が必須で、 DevRev との通信に WebSocket Secure (wss) を使う。 企業ファイアウォールやプロキシが WebSocket、あるいは接続先ホスト宛の 443 通信を ブロックしていると疎通できない。フィルタ製品によっては、デスクトップ版が丸ごと弾かれることもある。

対処

wss / 443 の通信を許可する

IT・ネットワーク担当に、次の通信の許可（allowlist 追加）を依頼する。

プロトコル : wss://  (WebSocket Secure)
ホスト    : app.devrev.ai
ポート    : 443       (HTTPS / WSS の標準ポート)

切り分けの順番はこう考えると早い。

  1. まず Web 版で疎通確認する（ブラウザで開けるか）。
  2. Web 版が通ってデスクトップ版だけ落ちるなら、wss / 443 のブロックを疑う。
  3. macOS の場合は、初回起動時の「ローカルネットワークアクセス許可」も確認する。
出典 / 注記

.devrev.ai の API / WebSocket ドメインは allowlist へ個別追加が必要な場合がある。 正確な要件は DevRev 公式ドキュメント を確認のこと。
