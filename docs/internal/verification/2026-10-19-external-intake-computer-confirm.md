| 入口 | 想定ユーザー | 流れ（要約） |

## 5. 判断材料（Computer 向けメモ・Cursor 整理）

| 観点 | GitHub Issue 先 | PR 先 |

| 投稿ハードル | 低い | 高い（git / スキーマ） |

## 7. Computer 回答（2026-10-19）

**回答者**: Computer（オーナー判断を反映）  
**回答日**: 2026-10-19  

**結論**: 外部の**標準入口はGitHub Issue（テンプレート）**、直接PRは慣れた投稿者向けの任意入口として併存させる。GitHub IssuesスナップインによるGitHub Issue → DevRev ISS取り込み設定は**完了済み**（2026-10-21 オーナー訂正）。投稿・PRは提案であり、採用決定後にComputerが裏取り・draftと公開作業を管理し、人のプレビュー確認・PRレビュー・マージを経て公開する。取り込まれたISSと公開作業用ISSの重複・リンクの扱いは初回実例で確認する。DevRev Issueは外部に見せない。

**チェック結果（4.x）**:

- 4.1 方針: 「GitHub Issue本線＋PRオプション」を採用。GitHub Issuesスナップインの**取り込み設定は完了済み**だが、取り込みの動作実績・公開作業用ISSとの関係は未確認。Computerが採用後の公開作業を整理し、公開採否の最終判断は人間。PR受信だけで採用・掲載を決めない。
- 4.2 Computer: 採用後、重複・機密情報・匿名化・根拠とサイトの既存schemaを確認し、裏取り済み内容のdraftとDevRev上の公開作業を管理する。取り込まれたISSがある場合は、新しいISSを機械的に二重起票せず、使い分け・リンクを確認する。既存 `aruaru-publish` はComputer起点の下書き＋Issue作成用であり、外部GitHub Issue/PRの取り込み・採否判断を自動化するスキルではない。旧 `devrev-aruaru-add` は別データ形式につきサイト公開に使わない。
- 4.3 連携: オーナーは外部PRに後から自身が**PRコメントでISS番号を記入する運用を試したい**。これを尊重するが、GitHub for DevRevの確認済み資料にはブランチ、コミット、PRタイトル/本文へのID記載があり、**PRコメントのみで後付けの関連付け・ステージ遷移が起きるかは未検証**。最初の実例ではマージ前にIssueへのコード変更リンクとステージを確認する。動かなければCursorがPRタイトル/本文へIssue IDを追記して再確認し、必要ならステージを手動確認・更新する。PRコメントだけで自動完了するとは記事で断定しない。
- 4.4 記事: DA-9/DA-10では**Computer起点のみ実走済み**、外部Issue/PR起点は未実走の運用案と明示。DA-9の外部行は「PR本線」から「GitHub Issue本線＋PR任意」へ変更し、DA-10の比較表と図も合わせる。GitHub Issuesスナップインの設定は完了済みだが、記事では「投稿を取り込む予定」程度に留め、設定・取り込み実績・公開フローとの関係を断定しない。

**OPERATIONS 変更が必要か**: §11を上記の採用ゲート・役割・PRコメント未検証条件で補記した。`docs/devrev-github-issue-policy.md` の「GitHub Issueは使わない」も「開発タスク管理には使わない、外部投稿の受け口として使う」に限定。2026-10-21の訂正で、両文書にGitHub Issuesスナップイン設定済みを反映し、「自動同期しない」という誤記を除去した。設定自体には触れない。これらは**未コミット**で、Cursorのレビュー/PRに委ねる。

**DevRev 上の記録先**: 新しいIssueはまだ起票しない。DA-9執筆 ISS-78 / DA-10執筆 ISS-79への引き継ぎを想定。外部PR経路を検証する必要が生じたら、Computerがサイト用PROD-11配下に検証Issueを起票する。

## 8. サイト掲載用の投稿案内（Cursor実装待ち）

**Cursorへのコメント（オーナー了承・2026-10-19）**: 既存のAboutページにGitHub Issue投稿ボタンと「PRを書く必要はありません」の案内がすでにあることを、オーナーが確認した。新規の入口や別ページを作る必要はない。既存の「あるあるを投稿する」セクションを保ち、以下の短い案内を追加する。サイト掲載文とDA-9/DA-10の外部投稿経路を整合させる。Web実装・Git/PRはCursor担当。Computerは文案と方針を用意したのみで、サイト本体は未変更。

現状、`web/src/pages/about.astro` に「GitHub Issueで投稿する」ボタンと「PRを書く必要はありません」があり、標準入口の導線は実装済み。以下はそのセクションへ追加する短い説明文の提案であり、まだサイトへ反映・公開していない。

> **あるあるを投稿する**
>
> DevRevで困ったことや解決したことを、GitHub Issueからお寄せください。症状と対処が分かれば投稿できます。原因が未確認でも構いません。
>
> 投稿にはGitHubアカウントが必要です。組織名・個人情報・社内チケット番号・認証情報など、公開できない情報は書かないでください。投稿内容は確認・裏取りしたうえで採用を判断し、必要に応じて匿名化して掲載します。**投稿した内容が必ず掲載されるわけではありません。**
>
> PRを書く必要はありません。GitHubに慣れた方は直接PRでの提案も可能です。PRもレビュー・採用判断の後に反映します。

配置の提案: 既存Aboutの「あるあるを投稿する」セクションを拡充し、既存の `issueUrl` ボタンを主CTAとして維持。任意のPR導線は同セクションのテキストリンクなど控えめにする。DevRev Issue/内部の採用フローや未検証のPRコメント連携は外部向けのページに出さない。必要ならヘッダー/フッターからAboutの該当セクションに到達できるかCursorが確認。実装・Git・PR・公開はCursor担当。
